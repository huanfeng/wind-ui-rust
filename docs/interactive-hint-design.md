# 交互式提示（hint）设计

> 状态：已定方案，待实现。起因是清风设置端把选项说明收进标题后的 ⓘ 图标（悬停才显示），
> 暴露出现有 tooltip 的三处不足。

## 1. 要解决什么

现有 `Element::tooltip` 是宿主层的**纯绘制浮层**（`app/tooltip.rs`）：

1. 位置取**指针点**（右下偏移，放不下再翻），不是控件——鼠标一动浮层就跟着挪，
   对「说明某个控件」的语义不对。
2. 浮层不参与命中，鼠标**移不进去**，一移开就消失。
3. 浮层里的字是普通绘制文本，**选不了、复制不了**。较长的说明（路径、示例、规则）
   用户想抄走时没有办法。

另外外观可调的只有 `bg/text/corner/max_width/border/delay_ms`，内边距、行距、字号是写死的常量，
长文本排版不好看，宿主无从调整。

## 2. 目标与非目标

**目标**

- 提示**锚定在节点上**：贴在锚点下方，放不下翻到上方，不跟指针。
- 鼠标可以**移进提示**，提示保持显示；可**选中并复制**其中文本。
- **点击锚点固定**提示：固定后移开也不收，点别处或 Esc 才关。
- 外观由 `TooltipTheme` 提供足够多的定制项（§6）。
- 现有 `Element::tooltip(..)` 的行为与写法**完全不变**。

**非目标**

- 不做富交互内容（按钮、链接、输入框）——内容只有文本。要放控件用 `popup`。
- 不等 `anchored-placement-design.md` 落地：本方案复用现成的树内 `popup` 摆放
  （锚在父节点、可翻边、顶层不裁剪、锚点滚出视口自动收起），将来统一摆放时自动受益。
- 不改 toast / 菜单 / 托盘提示。

## 3. 方案：用树内 popup 实现，宿主只驱动开合

不在宿主层再造一套交互浮层，而是把提示做成锚点的一个 **`popup` 子节点**：

```
锚点节点（ⓘ 图标）
└─ popup 子节点（受 open 信号控制）
   └─ RichText（可选中、Ctrl+C、右键复制）
```

关键性质：popup 是锚点的**子孙**，所以「指针在提示上」与「指针在锚点上」在悬停链
（`ancestor_chain`）里是同一件事——宿主只需判断「悬停链里是否含该锚点」，鼠标从图标移进
提示时悬停链不断，天然满足「可移进去」。摆放、顶层绘制、命中、选择、复制都是现成能力。

### 3.1 API

```rust
// 新增，与 tooltip 并列；两者同时设置时 hint 优先（见 §5）。
Element::icon(..).hint("较长的说明文本");                  // 默认选项
Element::icon(..).hint_with("说明", HintOptions::default().pinnable(true));
```

- `hint` 收 `impl Into<TextContent>`（沿用 i18n 的 `t!` 路径）。
- `HintOptions`：`pinnable`（点击固定，默认 true）、`placement`（`Below` 默认 / `Above` /
  `Auto`）、`max_width`（覆盖主题）。其余外观走主题，不进选项。
- 构建期把 popup 子节点和 `open: Signal<bool>` 一并挂好，调用方不接触信号。

## 4. 行为（宿主状态机）

宿主为 hint 新增一个小状态：当前候选锚点、悬停起点、离开起点、是否已固定。每次指针事件后
按悬停链更新，每帧按时间推进。

| 状态 | 进入条件 | 动作 |
| --- | --- | --- |
| 关闭 | 初始 / 离开宽限期满 / Esc / 点外部 / 锚点滚出 | `open=false` |
| 待开 | 悬停链首次含某 hint 锚点 | 计时 `open_delay`（默认 120ms） |
| 打开 | 待开满时 | `open=true`；同一时刻只允许一个 hint 打开，新开的先关旧的 |
| 宽限 | 打开后悬停链**不再含**该锚点 | 计时 `close_delay`（默认 180ms）；期间指针回到锚点/提示则回「打开」 |
| 固定 | 打开时点击锚点 | 不再宽限收起；点外部（popup 自带的 dismiss）或 Esc、再点锚点关闭 |

要点：

- **宽限期**用来跨过锚点与提示之间的缝隙（`gap`），否则指针一经过缝隙就收起。
- 在**提示内部按下鼠标拖选文字**不能触发收起：悬停链仍含锚点，且按下发生在 popup 内，
  popup 的 dismiss 判据本就把「点在自身内」排除在外。拖选过程中指针即使划出提示边界，
  走既有的指针捕获，不进入宽限。
- 选区存在时不因宽限期满而收起（用户正在复制）；选区清空后再进入宽限。
- 触发延时与现有 tooltip 的「重新计时 / 按下抑制 / 请求到点一帧」同一套思路，沿用
  `anim::request_repaint_after`，等待期不空转续帧。
- 局部重绘：浮层在树内，脏区由 popup 自己上报，不必再像 tooltip 那样专门判
  `is_overlay`。

## 5. 与现有 tooltip 的关系

- `tooltip` 不动：仍是指针锚定、不可交互，适合图标按钮的一句话名称。
- 同一节点（或其祖先链上更近的）既有 `hint` 又有 `tooltip` 时，**hint 优先、tooltip 不弹**，
  避免两层同时出现。判据放进 `Tree::node_tooltip` 同源的一处，不在两个地方各写一份。
- 文档里写明取舍：**说明性、可能较长、需要复制 → hint；控件名称提示 → tooltip**。

## 6. 外观定制（`TooltipTheme` 扩展）

hint 与 tooltip 共用 `TooltipTheme`，新增字段均 `Option`，缺省值保持现有观感，
旧主题文件不受影响：

| 字段 | 含义 | 缺省 |
| --- | --- | --- |
| `pad_x` / `pad_y` | 内边距（逻辑 px） | 8 / 4（现状）；hint 用 12 / 8 |
| `font_size` | 字号 | `metrics.font_sm` |
| `line_height` | 行距倍数 | 1.0；hint 用 1.4（长文本更透气） |
| `shadow` | 投影（偏移/模糊/色），`None` 不画 | tooltip 无；hint 有 |
| `gap` | 与锚点间距 | 6 |
| `open_delay_ms` | hint 弹出延时 | 120 |
| `close_delay_ms` | hint 离开宽限 | 180 |
| `hint_max_width` | hint 换行上限 | 360 |
| `selection_bg` | 选区底色 | 沿用 `RichText` 的选区色 |

`max_width` / `delay_ms` 仍管 tooltip，hint 用各自的 `hint_*` / `open_delay_ms`，
避免一个字段在两种提示里含义漂移。tooltip 的内边距、字号、行距同样改读这几个字段
（缺省即旧常量），一并解除「写死」。

## 7. 清风设置端的接入

- `widgets::desc_badge`（静态说明）改为在 ⓘ 图标上 `.hint(text)`；说明随状态变化的
  信号型说明用 `hint_signal`（构建期给信号，打开时读当前值）。
- 设置窗主题里调 `TooltipTheme`：pad / line_height / shadow 等，不再靠 `max_width` 一项硬撑。
- 「选项说明」缺省值与「界面细节」窗口里的文案不变；只是图标模式下的浮层更好用。
- 依赖：windui 当前 0.37.0 已发，本特性进下一个版本（暂定 0.38）。设置端先用
  `--config` 本地联调，**不提交路径依赖**；windui 发版由维护者执行，发版后设置端再升版本号。

## 8. 测试

- 状态机单测（纯函数化，不依赖窗口）：待开→打开→宽限→回到锚点；宽限期满收起；
  固定后移开不收、Esc 收；同时只开一个；选区存在时不收。
- 摆放：下方放不下翻到上方；两侧都放不下贴边（沿用 popup 既有用例，补一条 hint 的）。
- 悬停链：指针在 popup 内等价于在锚点上（节点命中测试）。
- 选择复制：hint 内容可 Ctrl+C，取到的是原文（含换行）。
- 兼容：只设 `tooltip` 的节点行为不变（既有用例全过）；`hint` + `tooltip` 同设只出 hint。
- 离屏截图：`--hover X Y`（已有，截屏前合成悬停）核对 hint 的位置与外观。

## 9. 风险与待办

- popup 的 `dismiss` 逻辑目前挂在 `Down` 上，hint 的「悬停即开」要确认不会被同一次点击
  既当作「点外部」又当作「点锚点」处理；固定态的点击切换需单独写进 hint 的锚点回调。
- 多行 `RichText` 的测量宽度走 `hint_max_width`；超长无空格串（路径）要允许任意位置断行。
- 触屏/无悬停设备：只有点击固定一条路，行为已覆盖（点击即固定）。
- 可访问性：hint 内容应并入锚点的无障碍描述（`accessibility.rs` 现有 tooltip 的做法同源）。
